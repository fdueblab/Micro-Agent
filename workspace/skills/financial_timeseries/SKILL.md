你正在生成一个**金融时间序列预测模型**（汇率/价格/交易量/额度预测等）。时序任务有两条铁律，违反即失效：

## 铁律 1：防时序泄漏

1. **切分**：按时间顺序前 80% 训练 / 后 20% 测试，禁止 `train_test_split(shuffle=True)`
2. **特征**：只用预测时点已知的信息——滞后特征（`shift(k)` 且 k ≥ 预测步长）、过去窗口的滚动统计、日历特征（星期/月末）；禁止当期特征、禁止全序列统计量（含未来数据）
3. **标准化**：均值/方差仅用训练段计算
4. **重采样禁止**：SMOTE 会打乱时间结构，时序任务禁用；不平衡时用 class_weight

自检方法：对每个特征问"预测当天早上我能拿到这个数吗？"——答案是否则该特征泄漏。

## 铁律 2：必须对比朴素基线

朴素基线（下一期 = 最后一期值）在金融时序上极强，模型打不过它等于没有价值：

- 实现时同时计算：模型 MAPE vs 朴素基线 MAPE，两者并列写进 test_results 与 model_summary
- 模型接近随机游走数据（如日频汇率）时略逊于朴素基线是领域共识，如实汇报并说明，禁止掩饰
- 方向准确率 >55% 才有信息量（50% = 抛硬币），一并汇报

## 模型选型（按复杂度递增，单文件交付优先轻量）

1. 朴素/季节性朴素（也是 no_training 约束下的合理方案）
2. 线性回归 + 滞后特征（可解释，常胜过复杂模型）
3. ARIMA（statsmodels，依赖声明带版本）
4. GradientBoosting + 滞后/滚动特征（多变量主力）

禁止为单文件交付引入 LSTM/torch，除非用户明确要求。

## 输入防御（时序特有）

`main_process` 必须校验历史序列长度 ≥ 最小窗口（特征所需最大滞后阶数），不足时降级返回 `{"prediction": None, "confidence": 0, "reason": "历史序列不足 N 期"}`——禁止崩溃，禁止强行预测。

## 评估

MAPE 为主指标，RMSE/MAE 注明单位与量纲，方向准确率辅助。滚动验证（walk-forward）优于单次切分，条件允许时优先使用。
