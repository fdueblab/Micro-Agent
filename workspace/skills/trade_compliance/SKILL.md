你正在生成一个**跨境贸易合规类算法模型**（名单筛查/HS编码归类/单证审核等）。合规场景的红线与通用分类任务不同：

## 核心原则：宁缺毋滥 + 每条结论带依据

1. **未命中必须返回 None/需人工**：名单没匹配上、品类没识别出时，输出 `None + "需人工处理"`，**绝对禁止**随机选编码或强行给结论——申报错误/漏放行的合规责任远大于自动化率
2. **每条结论带依据**：命中的关键词、名单条目、规则名必须写进 `reason`（审计追溯要求）
3. **规则表与逻辑分离**：`HS_RULES`/`DOC_RULES`/名单作为模块级常量，每条注明来源（监管文件/业务制度）

## 名单筛查：模糊匹配是核心技术

真实名单匹配从不全等（大小写/空格/别名/音译/缩写），必须标准化 + 分层匹配：

```
标准化：去标点 → 压空白 → 转大写 → 常见别名映射（CO LTD→COMPANY LIMITED）
匹配分层：全等(1.0) > 包含(0.9) > token重叠≥0.8(0.7+)，超阈值即命中
```

禁止 `name == list_entry` 式全等匹配（真实数据几乎永远匹配不上）。

## HS 编码归类：关键词规则 + 置信度分层

品名文本命中规则表关键词（可多个加权）→ 输出编码 + 置信度 + 命中关键词；未命中 → `hs_code=None, confidence=0, reason="需人工归类"`。

## 单证审核：规则引擎模式

跨字段一致性校验（币种一致/金额区间/必填字段），每条规则独立捕获字段缺失与类型错误（转为"该规则不通过"而非崩溃），输出 pass/reject + 未通过规则清单。

## 数据防御（单证数据脏值极普遍）

- 金额字段：非数值、负数、科学计数法字符串都要防御
- 币种缺失：降级 + 提示，禁止默认 USD
- 多币种金额比较前先归一化（汇率快照注明日期）

## 评估与汇报

- 匹配/归类任务：精确率与召回率并列（漏放行 vs 误拦截的业务代价不同，说明权衡）
- **规则覆盖率/自动化率**单独汇报：多少比例样本可自动判定、多少进入人工——这本身是核心业务指标
